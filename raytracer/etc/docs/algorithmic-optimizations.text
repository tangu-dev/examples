# Algorithmic Optimizations for Raytracer

This document outlines key algorithmic, mathematical, and data-structure optimizations to accelerate the raytracer execution and improve rendering convergence.

---

## 1. Ray-Sphere Math Simplification & Early Reject

### Quadratic Equation Simplification
The ray-sphere intersection equation for ray P(t) = Q + t * d and sphere with center C and radius r is:
(Q + t * d - C) . (Q + t * d - C) = r^2

Let oc = C - Q. Expanding yields:
(d . d) * t^2 - 2 * (d . oc) * t + (oc . oc - r^2) = 0

Let a = d . d, h = d . oc, and c = oc . oc - r^2.
By normalizing the ray direction d upon creation (|d| = 1), a = d . d = 1.0 identically.

The discriminant and root distance equations simplify to:
discriminant = h^2 - c
t = h - sqrt(h^2 - c)

- Impact: Normalizing ray direction upon ray creation eliminates calculating (d . d) and dividing by a in every single sphere intersection check.
- Precomputing radius^2: Store radius_squared on Sphere struct creation to avoid multiplying (radius * radius) inside hit loops.

### Early Geometric Reject
If ray origin Q is outside the sphere (oc . oc > r^2 => c > 0), and h = d . oc < 0 (ray direction points away from sphere center):
- Both quadratic roots t1 = h - sqrt(h^2 - c) and t2 = h + sqrt(h^2 - c) are strictly negative (t < 0).
- Since both roots lie behind the ray origin (t < 0.001), the ray cannot intersect the sphere in front of the camera.
- Returning miss () immediately when h < 0 and c > 0 skips discriminant and sqrt computations without false negatives.

## 2. Cosine-Weighted Hemisphere Sampling

### Analytical Sampling vs Rejection Sampling
Current implementation uses rejection sampling in a `while true` loop (generating 3 random floats in [-1, 1], testing if inside unit sphere, and normalizing). On average, this requires ~1.91 iterations and ~6 random float calls per bounce.

Cosine-weighted sampling generates directions with probability density p(w) = cos(theta) / pi directly using 2 random floats u1, u2 in [0, 1):
r = sqrt(u1), phi = 2 * pi * u2
v_local = (sqrt(u1) * cos(2 * pi * u2), sqrt(u1) * sin(2 * pi * u2), sqrt(1 - u1))

Transforming v_local to an Orthonormal Basis (u, v, n) aligned with normal N yields the world direction.

- Estimator Unbiasedness: (f_r * L_i * cos(theta)) / p(w) = ((rho / pi) * L_i * cos(theta)) / (cos(theta) / pi) = rho * L_i.
- Impact: Concentrates sample rays where diffuse reflection is strongest, reducing Monte Carlo variance/noise and eliminating rejection loop overhead.

## 3. Russian Roulette Ray Termination

At bounce depth d <= 7 (e.g. after 3 bounces), terminate deep rays probabilistically instead of tracing up to max-depth (10 bounces) unconditionally:
- Terminate with probability q (e.g. q = 0.5), returning black (0, 0, 0).
- Continue with probability 1 - q, scaling surviving ray radiance by 1 / (1 - q).

- Unbiased Estimator: E[Radiance] = q * 0 + (1 - q) * (Radiance / (1 - q)) = Radiance.
- Impact: Reduces CPU workload spent on deep bounces carrying negligible radiance (< 1% contribution to final pixel).

## 4. Camera Inner Loop Hoisting & I/O Reduction

### Vector Distributive Law
For a pixel at integer coordinates (x, y) and jitter offsets (rx, ry):
P_sample = P_00 + pixel_delta_u * (x + rx) + pixel_delta_v * (y + ry)

By distributive law:
P_center = P_00 + x * pixel_delta_u + y * pixel_delta_v
P_sample = P_center + rx * pixel_delta_u + ry * pixel_delta_v

- Impact: Computing P_center once per pixel outside the sample loop eliminates redundant per-sample coordinate math.
- For samples-per-pixel == 1 (rx = ry = 0), P_sample = P_center directly.
- Removing (echo y) inside the main render loop eliminates heavy stdout I/O overhead.
